# دليل اختبار APK v13 مع mock server على Termux

## تنبيه مهم قبل البدء

نسخة APK v13 التي بُنيت سابقًا مضبوطة على بيئة **production**، ولذلك تتصل بعنوان Render المضمّن داخل التطبيق. تشغيل mock server في Termux وحده لا يغيّر عنوان الاتصال داخل APK v13.

لذلك يوجد مساران:

| المسار | الاستخدام |
|---|---|
| APK v13 الحالي | اختبار الخريطة مع Render والبيانات الحقيقية، وليس مع mock server المحلي |
| APK محلي جديد | اختبار الحالات `normal / delay / stopped / emergency` مع Termux |

لا تحاول وضع كلمة مرور أو سر داخل Termux. mock server يعمل في الذاكرة فقط ولا يتصل بـ Supabase أو Render.

## المتطلبات

يحتاج الهاتف إلى Android، وتطبيق Termux، واتصال شبكة إذا كان الخادم يعمل على جهاز آخر. إذا كان Termux والتطبيق على الهاتف نفسه، يمكن استخدام `127.0.0.1`. يجب السماح للتطبيق بتثبيت APK من المصدر الذي ستفتح منه الملف عند الحاجة.

## المسار الأول: اختبار APK v13 الحالي

ثبّت APK v13 وافتح التطبيق ثم ادخل إلى الخريطة. في هذه النسخة لا تشغّل mock server بهدف تغيير البيانات؛ التطبيق سيستمر باستخدام عنوان Render المضمّن. اختبر ظهور الخريطة، علامات المحطات، بطاقة القطار، التتبع، والخريطة العامة وفق البيانات المتاحة في الإنتاج.

إذا كان هدفك اختبار حالات التأخير والطوارئ تحديدًا، انتقل إلى المسار الثاني وابنِ نسخة محلية منفصلة. لا تستبدل نسخة الإنتاج محليًا باسم أو إعدادات إنتاجية.

## المسار الثاني: اختبار mock server فعليًا

### 1. تثبيت Python في Termux

افتح Termux ونفّذ:

```bash
pkg update -y
pkg install python -y
termux-setup-storage
```

وافق على صلاحية التخزين عند ظهورها.

### 2. وضع ملف mock server في الهاتف

نزّل ملف `mock_live_trains_server.py` إلى مجلد Download في الهاتف، ثم نفّذ في Termux:

```bash
mkdir -p ~/winrah-mock
cp /sdcard/Download/mock_live_trains_server.py ~/winrah-mock/
cd ~/winrah-mock
```

تحقق من وجود الملف:

```bash
ls -l mock_live_trains_server.py
```

### 3. تشغيل الخادم

ابدأ بالحالة الطبيعية:

```bash
python mock_live_trains_server.py --host 0.0.0.0 --port 18080 --interval 2 --scenario normal
```

اترك هذه النافذة مفتوحة. إيقافها يكون بواسطة:

```text
Ctrl + C
```

ولمنع الهاتف من النوم أثناء الاختبار يمكن تنفيذ الأمر التالي في نافذة أخرى:

```bash
termux-wake-lock
```

وعند الانتهاء:

```bash
termux-wake-unlock
```

### 4. التحقق من الخادم قبل فتح التطبيق

افتح جلسة Termux ثانية، ثم نفّذ:

```bash
curl http://127.0.0.1:18080/health
curl http://127.0.0.1:18080/trains
curl http://127.0.0.1:18080/stations
```

يجب أن يعيد `/health` حالة `ok`، ويجب أن يعيد `/trains` ثلاثة قطارات محاكاة، كما يجب أن يعيد `/stations` محطات الضواحي الثلاث.

## بناء APK محلي للاختبار

بما أن APK v13 إنتاجي، يلزم بناء نسخة محلية منفصلة من مستودع Android. من مجلد المشروع نفّذ:

```bash
VERSION_CODE=14 VERSION_NAME=1.0-map-v14-local ./gradlew --no-daemon --offline test assembleDebug \
  -PWINRAH_API_BASE_URL=http://127.0.0.1:18080/ \
  -PWINRAH_API_ENVIRONMENT=local \
  -PWINRAH_API_WRITES_ENABLED=false
```

سيكون الملف الناتج غالبًا في:

```text
app/build/outputs/apk/debug/app-debug.apk
```

انسخ الملف إلى الهاتف، ثم افتحه من Download وثبّته. هذه النسخة مخصصة للاختبار المحلي فقط، ولا ترفعها إلى الإنتاج ولا تستخدمها بدل APK الإنتاج.

إذا كان mock server يعمل على حاسوب آخر وليس على الهاتف، استخدم عنوان IP المحلي للحاسوب بدل `127.0.0.1`، مثل:

```bash
-PWINRAH_API_BASE_URL=http://192.168.1.20:18080/
```

ويجب أن يكون الهاتف والحاسوب على الشبكة نفسها، وأن يسمح جدار الحماية بالمنفذ `18080`.

## جدول اختبار الحالات

بعد تثبيت النسخة المحلية، افتح الخريطة قبل تغيير الحالة، ثم نفّذ الأوامر التالية من جلسة Termux الثانية.

| الحالة | الأمر | المتوقع في التطبيق |
|---|---|---|
| طبيعي | `curl 'http://127.0.0.1:18080/scenario/set?value=normal'` | علامة خضراء، حركة، سرعة غير صفرية، وبطاقة «يعمل بشكل طبيعي» |
| تأخير | `curl 'http://127.0.0.1:18080/scenario/set?value=delay'` | علامة وبطاقة باللون البرتقالي، حالة تأخير، وسرعة أقل |
| توقف | `curl 'http://127.0.0.1:18080/scenario/set?value=stopped'` | علامة رمادية، سرعة صفر، وإيقاف المؤثر النبضي |
| طوارئ | `curl 'http://127.0.0.1:18080/scenario/set?value=emergency'` | علامة حمراء، تنبيه واضح، وسرعة صفر |

بعد كل أمر انتظر دورة تحديث واحدة أو دورتين، ثم أعد طلب:

```bash
curl http://127.0.0.1:18080/scenario
curl http://127.0.0.1:18080/trains
```

| 7 | الضغط على «الخريطة العامة» | ناجح / مشكلة |

## العودة الآمنة إلى الإنتاج

بعد انتهاء الاختبار، أوقف mock server بواسطة `Ctrl + C`، ثم أوقف قفل الاستيقاظ:

```bash
termux-wake-unlock
```

بعدها أعد تثبيت APK الإنتاج الذي تستخدمه. لا تستخدم APK المحلي في الإنتاج، ولا تغيّر متغيرات Render أو Supabase من أجل هذا الاختبار.

## عند عدم ظهور القطار

تحقق أولًا من أن `/health` يعمل داخل Termux. إذا كان يعمل، تحقق من أن APK المثبت هو النسخة المحلية وليس v13 الإنتاجية. إذا كان الخادم على حاسوب آخر، تحقق من عنوان IP والشبكة وجدار الحماية. لا تستخدم `127.0.0.1` عندما يكون الخادم على جهاز مختلف عن الهاتف.

## تسجيل نتيجة الاختبار

أرسل نتيجة كل حالة بهذا الشكل:

```text

اتجاه العلامة: ناجح/مشكلة
البطاقة السفلية: ناجح/مشكلة
delay: ناجح/مشكلة — وصف مختصر
stopped: ناجح/مشكلة — وصف مختصر
emergency: ناجح/مشكلة — وصف مختصر
المحطات والتكبير: ناجح/مشكلة
التتبع والخريطة العامة: ناجح/مشكلة
```
